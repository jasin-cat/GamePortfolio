作品概要

ピッチャーが投げるボールを、ストライクゾーンで捕るキャッチボールゲームです。 「Ready... Go」の合図のあと、ピッチャーがストライクゾーン内のランダムな位置へボールを投げます。 投げるたびに、ボールが届く位置に円いリングが表示され、届くまでの時間に合わせて小さくなっていきます。 リングが閉じる瞬間に、ボールが届く位置をクリックするとキャッチです。 タイミングと位置のずれが小さいほど Perfect・Great・Good と高い評価になり、得点が画面に浮かび上がります。 10球投げ終わると合計点が表示され、リトライボタンで最初から遊べます。

操作方法

  • マウスクリック：ボールが届く位置をクリックしてキャッチ

技術解説

  • ボールは、到達時間 t と目標までの距離から、水平方向は「距離 ÷ t」、上下方向は重力の分を足した初速を求めて Rigidbody に与える。 これで投げるたびに速さが変わっても、必ずストライクゾーンの狙った位置に届く。
  • 判定は、ボールがストライクゾーンに入った時刻とクリックした時刻の差、 目標位置とクリック位置の距離をそれぞれ0〜1に正規化し、その平均で Perfect・Great・Good・Miss を決める。
  • リングはUIのImageに自作シェーダーを使い、半径を1から0へ小さくしていく。 目標のワールド座標を毎フレーム WorldToScreenPoint で画面座標に変換して、リングの位置を合わせる。
  • 投球・判定の完了・得点の変化はR3のSubjectとReactivePropertyで通知し、 GameFlowControllerが購読して投球・キャッチ・得点・UIをつなぐ。
  • Ready・Go の文字送りや得点の浮かび上がりは、UniTask と LitMotion で待ち時間とアニメーションを順番に書いている。

設計の工夫と選択理由

「何を選んだか」と「なぜ選んだか」、比較した方法をまとめています。

設計要素 採用した方法 ねらい 比較した方法・避けた理由
ボールの投げ方 到達時間から初速を逆算し、Rigidbodyに速度を与える 速さを変えても必ず狙った位置に届き、届く時刻も前もって分かる AddForceで毎回同じ力を加える → 届く位置と時間が決まらず、リングの表示と合わせられないため
キャッチの判定 時間のずれと位置のずれを0〜1に正規化して平均する 「早すぎる・遅すぎる」と「場所がずれている」の両方を1つの評価にまとめられる 時間だけで判定する → どこをクリックしても捕れてしまい、位置を狙う意味がなくなるため
タイミングの見せ方 到達時間に合わせて縮むリングを、シェーダーで描く どこに・いつ届くかが一目で分かり、半径を変える値1つで描き直せる リングの画像を拡大縮小する → 線の太さまで一緒に変わってしまうため
機能どうしの連携 R3のSubjectで通知し、GameFlowControllerで購読してつなぐ 投球・キャッチ・得点・UIがお互いを直接知らなくてよい 直接メソッドを呼び合う → クラス同士の依存が増えるため
入力の受け取り Input SystemのInputActionをコードで作るクラス（CatchInput）にまとめる クリック位置をレイキャストで3D座標に直す処理を、判定のクラスから切り離せる 判定クラスの Update で毎フレーム入力を調べる → 判定と入力の処理が混ざるため

既知の課題と今後の改善予定

既知の課題

  • 球速の種類で、速い球（Fast）のときに到達時間を足し、遅い球（Slow）のときに引いているため、名前と実際の速さが逆になっている。
  • クリックしないとボールがストライクゾーンを通り過ぎても判定が終わらず、次の球が投げられない。
  • クリックした位置にコライダーがないとレイキャストが当たらず、クリックが無視される。
  • 投げる球数（10球）が変数ではなく、判定の式に直接書かれている。

次に改善したい点と、その理由

  • 球速の足し引きを直し、速い球・遅い球の差が分かるよう見た目でも区別する。駆け引きのあるゲームにするため。
  • ボールが通り過ぎてから一定時間クリックがなければ Miss にする。操作しなくてもゲームが止まらないようにするため。
  • ストライクゾーンと同じ面にクリック用の平面を置き、どこをクリックしても位置を取れるようにする。
